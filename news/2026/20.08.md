## Revival of @iconify-icons/ packages {#split-packages}

Iconify icon data is once again available in [@iconify-icons packages](/docs/icons/icons.html).

These packages have one file per icon in [IconifyIcon format](/docs/types/iconify-icon.html).

### Why were these packages abandoned?

There were several issues with old packages, the biggest one was large number of files.

Some icon sets have tens of thousands of icons, which required huge number of files (two per icon) in one directory.
Some file systems used on Windows could not handle it, so packages prevented development of various projects.

### Solution

New packages have a different structure, where instead of putting all files in one directory,
files are grouped by first letter of icon name: `[file]data/h/home-outline.js`.

Packages use `[prop]exports` field in `[file]package.json` to map icon names to file locations,
which also helps with auto completion in IDE.

So when you write this:

```js
import chatIcon from '@iconify-icons/solar/chat-square-outline';
```

File is actually imported from `[file]@iconify-icons/solar/data/c/chat-square-outline.js`.

This was not possible several years ago when Node.js just added `[prop]exports`, which was not fully supported by various tools.
Today this is possible.

### Breaking change

New components introduce a breaking change, so version number is bumped to `[num]2.0.0`.

Previously, it was possible to import icon data with and without `[file].js` extension:

```js
// Works in old and new version
import chatIcon1 from '@iconify-icons/solar/chat-square-outline';
// Works only in old version
import chatIcon2 from '@iconify-icons/solar/chat-square-outline.js';
```

In new version syntax with `[file].js` extension will no longer work.

### Purpose of packages

These packages export raw icon data, which can be used in various custom tools.

These are not icon components or SVGs.

For icon components, check out [premade icon components for React, Vue, Svelte and SolidJS](/docs/usage/svg-css/).
